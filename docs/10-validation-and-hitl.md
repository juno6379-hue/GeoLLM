# 10. 검증 및 Human-in-the-Loop (Validation and HITL)

## 1. 개요
LLM 및 자동화된 공간/ML 모델의 분석 결과는 공공 기관의 의사결정에 사용되므로 높은 신뢰성이 요구됩니다. Validation Agent를 통해 1차 교차 검증을 수행하고, 기준을 만족하지 못하면 Human-in-the-Loop(HITL) 프로세스를 통해 전문가의 검토를 받습니다.

## 2. Validation Agent 검증 항목

### 2.1 공간 (Spatial)
- **CRS 일치 여부**: 모든 분석 결과가 지정된 출력 CRS(EPSG:4326 또는 3857 등)를 준수하는가?
- **Geometry Validity**: 생성된 공간 객체가 유효한 지오메트리인가? (Self-intersection 등 점검)
- **공간 범위 이탈**: 분석 결과가 사용자가 요청한 버퍼나 바운딩 박스를 벗어나는가?
- **객체 일치성**: 텍스트로 요약된 객체 수(`structured_result.count`)와 실제 GeoJSON의 Feature 수가 일치하는가?

### 2.2 시간 (Temporal)
- **시간 범위 일치**: 분석에 사용된 데이터의 시점이 사용자 요청 범위와 일치하는가?
- **결측률 검증**: 시계열 분석 시 데이터 결측률이 임계값(예: 10%)을 초과하는가?

### 2.3 문서 및 표준 (Document & Standards)
- **출처(Evidence) 확인**: 제공된 인용구가 실제 DB/문서에 존재하는가?
- **버전 유효성**: 인용된 법령이나 S-100 표준이 만료되거나 폐기된 버전이 아닌가?

### 2.4 모델 및 전체 (Model & Overall)
- **신뢰도(Confidence)**: AI 추론 모델의 Confidence 스코어가 임계치(예: 0.8) 이상인가?
- **보안/권한**: 사용자가 접근 불가능한 등급의 데이터가 결과에 혼입되었는가?

## 3. 검증 결과 판정
Validation Agent는 각 항목을 검증한 후 다음 상태 중 하나를 반환합니다.
- `PASS`: 모든 검증 통과. 즉시 Map/Report 생성 단계로 전이.
- `WARNING`: 일부 불확실성이나 경미한 오류가 있으나 치명적이지 않음 (예: 과거 1일 전 데이터 사용). 결과물에 경고 문구 추가 후 전이 또는 HITL 결정.
- `FAIL`: 치명적 오류(객체 수 불일치, 권한 위반, 유효하지 않은 지오메트리 등). 자동 배포 차단 및 HITL 또는 재시도 전이.

## 4. Human-in-the-Loop (HITL) 프로세스
검토자(전문가, 관리자)가 개입하는 조건 및 절차입니다.

### 4.1 HITL 진입 조건
- Validation 결과가 `FAIL` 이거나 주요 `WARNING`인 경우.
- AI 모델의 Confidence가 지정된 수치 미만인 경우.
- "해상풍력 후보지 평가" 등 중요한 정책적/행정적 의사결정이 포함된 경우.
- 외부 공개용 보고서를 생성하는 경우.
- 다수의 Agent 결과가 서로 충돌(Conflict)한다고 Situation Interpretation Agent가 판정한 경우.

### 4.2 검토자 액션
Review UI 대시보드에서 전문가는 다음 중 하나의 액션을 취합니다.
1. **Approve (승인)**: 결과를 수용하고 다음 단계(Map/Report 생성)로 진행.
2. **Reject (반려)**: 결과를 폐기하고 태스크 실패 처리.
3. **Revise (수정 요청)**: 프롬프트 조건이나 파라미터를 변경하여 재분석(Retrying) 지시.
4. **Hold (보류)**: 추가 외부 데이터나 논의가 필요하여 일시 정지.

모든 결정 이력과 코멘트는 Audit Log에 기록되어 LLM 파인튜닝이나 프롬프트 개선 데이터로 재활용됩니다.
