# 17단계: 운항 이벤트와 선박 위치의 ETA 학습 적합성 감사

감사일: 2026-09-19. 실행 명령: `python scripts/audit_uport_eta_pairs.py`.

## 결합 기준

선박위치 API의 `callsgn`·`ptentYr`·`vyg`를 선박운항 API의 `callsgn`·`ptentVtsYr`·`vyg`와 정확히 일치시켰다. 운항 이벤트 이름이 `입항`인 레코드의 `jobDt`를 **도착 시각 후보**로 사용했다. 위치의 `updtTm`이 그 시각보다 앞서야 ETA 입력 후보로 인정했다. 제공자 시각에는 시간대 정보가 없으므로 시간대 변환이나 절대시각 정확도는 아직 검증하지 않았다. 실제 선박·항차 식별자와 인증키는 감사 결과에 출력하거나 저장하지 않았다.

13건의 운항 조회는 제공자의 데이터 없음 코드가 일반 응답과 다른 최상위 `resultCode` 형식으로 반환됐다. 감사 스크립트는 이를 데이터 없음으로 처리하고, 통신·제공자 오류와 구분한다. 페이지별 전체 건수는 제공자가 갱신하는 동안 변할 수 있다.

## 판단

현재 공개 API의 위치 응답은 이 감사에서 선박별 1회 스냅샷만 제공했다. 정확히 결합한 80건의 위치 시각도 모두 입항 이후이므로 ETA 학습 입력으로 사용하면 미래 정보 누출이 발생한다. **현재 수신 자료만으로는 LSTM·GRU·TFT의 ETA 학습 데이터를 만들 수 없다.** 모델 Registry의 `unavailable` 상태를 유지한다.

다음에는 시간순으로 반복된 **입항 전** AIS 위치 이력과, 같은 항차의 검증된 실제 입항 이벤트 이력을 확보해야 한다. 수집 기간, 이용 권한, 시각대, 호출부호·MMSI 연결 품질을 확인한 뒤 선박/항차 단위로 학습·보류 집합을 분리한다.
