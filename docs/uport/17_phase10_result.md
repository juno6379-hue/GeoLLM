# Phase 10 — U-Port 시나리오 검증 및 수용 상태

## 완료 작업

- 요구 문서의 자연어 시나리오 A~F를 동일한 계획·검증·실행 경계에서 테스트했다.
- 등록부에 S-101 항행 위험 조회와 선석 추천 근거 설명 기능을 명시했다. 두 기능은 공급 데이터/실행 Agent가 없으므로 `unavailable`이다.
- 검증되지 않은 ETA, 선박 위치, 추천 선석, 위험 객체가 실행 결과·근거·지도 레이어·서술로 생성되지 않는지 확인했다.

## 수정 파일

- `data/capability_registry.yaml`

## 신규 파일

- `tests/unit/test_uport_acceptance.py`
- `docs/uport/17_phase10_result.md`

## 재사용 구성과 아키텍처

- 기존 Capability Registry 검색, 다중 의도 의존성 정렬, `QueryExecutionContext`, `ExecutionValidator`, 도메인 실행 API를 재사용했다.
- 시나리오별 조건문을 추가하지 않았다. 등록부 메타데이터와 데이터 가용성 검증으로 차단 상태를 결정한다.

## 시나리오 실행 결과

| 시나리오 | 계획에서 식별한 핵심 기능 | 실행 결과 | 현재 누락 |
| --- | --- | --- | --- |
| A 입항 예정 선박 | AIS 조회·지도 표시 | 데이터 부족으로 차단 | 실시간 AIS/입항 예정 공급자 |
| B ETA 지연 선박 | AIS 조회·ETA 예측·지도 표시 | 데이터 부족으로 차단 | 실시간 AIS, 학습된 ETA 모델 |
| C 3번 선석 주변 선박 | S-101 선석·AIS 조회·지도 표시 | 데이터 부족으로 차단 | 실시간 AIS, 항만·선석 이름의 운영 ID 확인 |
| D 대기시간 감소 배정안 | S-101 선석·ETA·선석 최적화 | 데이터 부족으로 차단 | 운영 일정·제원·AIS·ETA 연결 |
| E 추천 선석 적합 이유 | 선석 최적화·추천 근거 설명 | 데이터 부족으로 차단 | 검증된 추천 결과와 제약 근거 |
| F 선박 주변 S-101 위험 객체 | AIS·S-101 위험 검색 | 데이터 부족으로 차단 | 검증된 선박 위치와 위험 객체 검색 Agent |

모든 시나리오의 실행 결과에서 가공된 `features`, `map_layers`, `evidence`, `narrative`는 비어 있다. E와 F는 해당 전문 기능이 등록부에 명시적으로 남으므로 단순 선석 피처 조회로 대체되지 않는다.

## 실행 및 테스트 결과

- A~F 수용 테스트와 기존 U-Port 계획·실행·예측·최적화·지도 테스트 34개 통과.
- 지도 → Agent → 지도 및 결과 목록 → 지도 UI 이벤트 테스트 2개 통과.
- S-101 선석을 지도에서 선택한 경우에는 기존 DB 경계 테스트에서 정확한 ID/데이터셋 버전, Evidence, GeoJSON을 확인했다. 이는 실제 운영 DB 연결의 성공 응답을 의미하지 않는다.

## 발견된 문제와 남은 작업

- A~F의 실제 업무 결과는 현 공급 데이터와 모델·Agent 부재로 수용 완료 상태가 아니다. 차단 동작과 결과 비조작만 검증됐다.
- 호스트 Python에서 PostGIS 인증 오류가 있어 실 DB 성공 API 호출을 재검증하지 못했다. 브라우저 세션도 없어 Leaflet 화면의 시각 검증은 수행하지 못했다.
- 다음 개발에서 AIS/항만 운영 공급자, 선석 길이·수심과 시간별 점유, 선박 식별자, ETA 학습·평가 데이터, S-101 위험 검색을 연결한 뒤 A~F를 실제 결과로 다시 실행해야 한다.
