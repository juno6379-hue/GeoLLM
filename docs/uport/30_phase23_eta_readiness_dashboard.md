# 23단계: ETA 데이터 준비 상태를 U-Port 대시보드에 표시

수집기가 매 주기 `eta_readiness_data/eta_readiness.json`을 원자적으로 갱신한다. 이 파일은 SQLite 원본과 달리 집계 건수와 검증 게이트만 담는다. 백엔드는 Docker 볼륨을 읽기 전용으로 마운트하고 `GET /api/v1/uport/predictions/eta-readiness`에서 허용된 집계 필드만 반환한다. MMSI, 호출부호, 좌표, 원천 인증키, 개별 학습 행은 API 응답에 포함되지 않는다. 보고서가 없거나 손상되면 503으로 표시한다.

U-Port 메인 대시보드의 **예측 결과 요약** 카드는 이 API를 읽어 위치 **갱신** 이력, 입항 전 갱신 항차, 학습·보류 건수를 표시한다. 데이터 준비와 모델 추론을 구분해, `export_ready=false`에서는 예측값을 표시하지 않는다. API 요청이 실패해도 0건이라고 추정하지 않고 상태 확인 불가로 표시한다.

운영 확인 시 누적 위치 갱신 이력은 1,151건, 입항 전 갱신 항차는 0개, 학습·보류는 각각 0건이었다. 이는 항내 위치 API의 `updtTm`이 공식적으로 **갱신시각**이며, 별도 입항 전 AIS 관측시각이 확보되지 않았기 때문이다.

## 필요한 원천자료와 확인 항목

입항 전 ETA 학습을 위해 제공기관에 요청할 최소 원천 계약은 다음과 같다.

1. **AIS 관측:** 2026년 울산항 접근 해역의 MMSI, 실제 수신·관측시각과 시간대, WGS84 위경도, 자료 기간·공간 범위, 정정·지연 게시 규칙.
2. **입항 정답:** `ptentDt`가 의미하는 실제 통과 지점과 확정 시점, `jobDt`와 차이가 날 때의 해석, 원천 시각의 시간대.
3. **이용 조건:** 원시 AIS 보관·학습·내부 대시보드 집계 게시의 허용 범위와 기간.

자료가 들어오면 `audit_uport_ais_candidate.py`로 열·연도·MMSI 겹침을, `audit_uport_ais_eta_join.py`로 항차별 입항 전 시간창과 중복 배정을 점검한다. 최소 30개의 독립 항차에 서로 다른 입항 전 AIS 관측이 두 건 이상 확인된 다음 학습·보류 분할을 실행한다. 현재 공유 Drive와 공개 [연안 AIS 통계 API](https://www.data.go.kr/data/15084033/openapi.do)의 해역별 집계 자료는 이 계약을 충족하지 않는다.
