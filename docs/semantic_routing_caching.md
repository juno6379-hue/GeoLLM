# 고급 시맨틱 라우팅 및 시맨틱 캐싱 아키텍처 가이드

본 문서는 해양공간 지능분석 플랫폼 오케스트레이터에 적용된 벡터 기반 시맨틱 라우팅(Semantic Routing)과 시맨틱 캐싱(Semantic Caching)의 구조와 동작 원리, 그리고 향후 체계화 전략을 설명합니다.

## 1. 아키텍처 개요

기존의 정규식(Regex) 단일 룰 기반 라우팅의 한계를 극복하기 위해, **BGE-M3 임베딩 모델**을 활용한 다중 Intent 분류 및 **FAISS 기반 영구 캐시** 계층을 도입하였습니다. 
이를 통해 파싱 정확도를 극대화하고, LLM 호출 빈도를 획기적으로 낮추어 전체 시스템 응답 속도를 0.1초 수준으로 개선했습니다.

## 2. 시맨틱 라우팅 (Semantic Routing)
`semantic_router.py`에 구현된 `SemanticRouter` 클래스는 사용자 질의의 문맥적 의미를 파악하여 최적의 에이전트로 라우팅합니다.

### 2.1 주요 플로우
1. **사전 정의 (Intent Vectors)**: `SPATIAL_SEARCH`, `KNOWLEDGE_SEARCH` 등 각 Intent별로 대표 발화 예시들을 미리 임베딩하여 메모리에 상주(Cache)시킵니다.
2. **벡터화 및 코사인 유사도 연산**: 사용자 질의가 들어오면 `bge-m3`를 통해 즉시 임베딩하고, 사전 정의된 예시 벡터들과 코사인 유사도(Cosine Similarity)를 계산합니다.
3. **규칙 기반 보정 (Rule-based Correction)**: 벡터 유사도를 통해 Intent가 `SPATIAL_SEARCH`로 확정되면, 정규식을 다시 한 번 가동하여 질의 내의 핵심 파라미터(기준 위치, 반경 거리, 검색 대상 등)를 즉각 추출합니다. 이를 통해 LLM 파서 호출 자체를 완전히 생략할 수 있습니다.

## 3. 시맨틱 캐싱 (Semantic Caching)
정규식 추출 범위를 벗어난 복잡한 질의는 GPT-4o-mini 파서로 전달되지만, 이 때 발생한 분석 결과(Intent 및 Execution Plan)를 재활용하기 위해 시맨틱 캐시가 작동합니다.

### 3.1 주요 플로우
1. **Cache Miss & LLM 파싱**: 캐시에 없는 새로운 복잡한 질의가 들어오면 기존대로 LLM이 파싱을 수행합니다.
2. **FAISS 벡터 DB 저장 (`add_to_cache`)**: 파싱이 성공하면 질의 원본 텍스트와 파싱 결과(JSON)를 FAISS 기반 벡터 DB에 영구 저장합니다.
3. **Cache Hit (`check_cache`)**: 이후 완전히 동일하진 않더라도 의미상 **95% 이상 유사한 질의**(예: "인천항 근처 5km 양식장 찾아줘" vs "인천항 5km 이내 양식장")가 접수되면, LLM 파서를 거치지 않고 FAISS에서 즉시 캐시된 파싱 계획을 가져옵니다.

## 4. 모듈 위치 및 구성
*   **`services/orchestrator/semantic_router.py`**: 라우팅(임베딩, 유사도 검사) 및 FAISS 캐시 로직을 전담합니다.
*   **`services/orchestrator/graph.py`**: 오케스트레이터의 LangGraph Workflow(parse_intent_node) 진입점에서 `SemanticRouter`와 `SemanticCache`를 가장 먼저 호출하여 트래픽을 단축 경로(Fast Path)로 우회시킵니다.
*   **저장소**: 캐시 파일은 애플리케이션 데이터 디렉토리 내 `geollm_cache/semantic_cache`에 영구 보존됩니다.

## 5. 엔터프라이즈급 확장을 위한 체계화 전략 (Future Roadmap)

초기 프로토타입을 넘어 현업 수준의 안정성과 확장성을 확보하기 위해 다음 4가지 핵심 전략을 기반으로 시스템을 고도화할 예정입니다.

### ① 다양한 질문 데이터셋 (Diverse Dataset) 구축
*   **현재**: 라우터 내부에 소수의 예시 문장이 하드코딩되어 있습니다.
*   **개선 방향**: 해양경찰, 항만청 등 도메인 전문가들이 실제 사용하는 수천 개의 질의(방언, 오타, 약어 포함)를 수집하여 JSON/DB화 합니다. 이를 FAISS 벡터 공간에 로드하여, 어떤 변형된 질문이 들어와도 정확한 의도(Intent)를 매핑할 수 있도록 임베딩 퀄리티를 극대화합니다.

### ② 도메인 규칙 기반 라우팅 (Domain Rule-based Routing) 강화
*   **현재**: 간단한 정규식을 통해 거리와 지명을 추출하는 수준입니다.
*   **개선 방향**: 벡터 유사도(의미 파악)의 한계를 보완하기 위해 해양 도메인 특화 개체명 인식(NER) 모델이나 정교한 텍스트 분석 파이프라인(SpaCy 등)을 결합합니다. 이를 통해 S-101 객체명, 반경, 날짜 조건 등을 오차 없이 추출하는 하이브리드 라우팅을 구현합니다.

### ③ Agent·Tool Capability Registry (에이전트 역량 레지스트리) 도입
*   **현재**: 오케스트레이터가 공간 분석, 지식 검색 등 각 에이전트의 역할을 사전에 하드코딩하여 알고 있습니다.
*   **개선 방향**: 마이크로서비스 아키텍처(MSA) 원칙을 적용하여, 신규 에이전트(예: 실시간 선박 트래킹 에이전트)가 부팅 시 자신의 역량(Capabilities)을 중앙 레지스트리에 동적으로 등록합니다. 오케스트레이터는 이 레지스트리를 참조하여 플러그인 방식으로 유연하게 작업을 위임합니다.

### ④ 지속적인 평가·개선 루프 (Continuous Evaluation & Feedback Loop)
*   **현재**: 라우팅에 실패한 질의는 LLM으로 Fallback 처리되며 끝납니다.
*   **개선 방향**: 라우팅 매칭 실패(UNKNOWN)나 캐시 적중률이 낮은 질의를 자동 수집하여 관리자 대시보드로 전송합니다. 관리자가 정답 의도를 레이블링(Human-in-the-Loop)하면, 해당 데이터가 **①번 질문 데이터셋**에 즉각 반영되고 벡터 캐시가 리빌드되어 시스템이 스스로 진화하는 자생적 루프를 완성합니다.
