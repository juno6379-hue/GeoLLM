# 독립 홀드아웃 준비와 인간 답변 채점 계획

작성일: 2026-11-02 (Asia/Seoul). 기존 개발 18문항, v6 144답변 및 승인 GOLD는 변경하지 않는다.

## 분리 원칙

1. 개발 평가: 기존 18문항은 오류 수정에 노출된 개발 자료다. AAA·BBB GOLD 검수 완료는 사용자 확인 기록을 따른다.
2. 전향적 홀드아웃: `benchmark/holdout_20261102_v1`에 별도 질문·GOLD·RQ2 오류·RQ4 복구 계약을 예약한다. 지금은 정답과 원천을 검증하고 평가 실행은 하지 않는다. 개발 중 내용을 이용해 수정하면 해당 사례는 독립 평가 자격을 잃는다.
3. 같은 원천·온톨로지나 오류 유형을 공유하는 경우 새 질문이라는 이유만으로 새 지역·새 데이터·새 오류 유형 일반화라고 주장하지 않는다. split과 실제 겹침 감사 결과를 함께 보고한다.
4. UI에는 준비 상태와 문항 수·계획만 기본 공개한다. GOLD 객체·정답·통제 오류의 기대 판정은 생성 프롬프트나 개발 trace에 제공하지 않는다. 동일 저장소의 논리적 분리이며 보안 격리된 비공개 평가 서버는 아니다.

## 최종 평가 전제

운영 수정 → 개발 18문항 점검 → 코드·프롬프트·모델 digest·소스 snapshot·생성 예산·평가 기준의 최종 동결 → 홀드아웃 GOLD 근거/독립 검수 확인 → 실행 gate 검증 → 8방법 비교 → 실패·미측정 포함 보고 순서로 수행한다. 이번에는 모델·운영 API 호출이나 비교 worker를 시작하지 않는다.

최종 시스템 동결은 기존 v6의 과거 동결로 대체하지 않는다. 실제 선택한 소스·모델·평가 버전을 새 manifest에 기록한다. 연구 범위를 운영 권위로 승격하거나 차단 정책을 평가 편의를 위해 낮추지 않는다. 실행 뒤 조건을 바꾸면 원본을 보존하고 새 실험으로 관리한다.

## 144답변 인간 의미 채점

사용자는 144개 모델 답변 채점 양식을 요청했다. 기존 GOLD 검수 완료가 144답변 인간 채점 완료를 뜻하지 않는다. `review/20261102_answer_semantic_review_v1`의 AAA·BBB 양식에 각자 판단을 입력하고 합의본으로 확정한다. 방법·모델 식별정보는 별도 매핑으로 분리한다. 답변 문체로 방법을 추측할 수 있는 잔여 한계는 공개한다.

판정은 승인 정답의 필수 의미·작업 완결·근거 적합성 및 잘못된 주장 여부를 함께 본다. 성공 상태나 기계계약 통과만으로 의미 정답을 자동 부여하지 않는다. 실제 답변 부재는 부재대로 표시하고 내용을 생성하지 않는다. 독립 작성 단계에는 상대 검수자의 답과 AI 점수를 제공하지 않는다.

가져오기 도구는 답변 ID/hash·GOLD identity·검수자 구분·입력 범위를 확인한다. 미입력은 미측정, 전체 분모와 평가 완료 분모를 함께 보고한다. 검수자 일치도와 합의 후 의미 정확도는 구분한다. 모든 답변을 사람이 채점하기 전에는 인간 정확도 완료로 승격하지 않는다. 서명·실제 판단을 AI가 대신 작성하지 않는다.
