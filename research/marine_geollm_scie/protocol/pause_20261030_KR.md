## 재개 순서

1. 이 문서와 `docs/geollm/remaining_work_roadmap.md` 상단을 먼저 읽는다. Git 상태·DB 잔여행·worker 부재·모델 digest를 재확인한다. UI/feedback의 별도 변경을 건드리지 않는다.
2. 같은 출력 폴더로 worker를 재개한다. DB의 embedding IS NULL만 처리하므로 저장된176건은 다시 계산하지 않는다.

```text
.venv/Scripts/python.exe -u -m scripts.complete_dataset_embeddings --output outputs/dataset_embedding_completion_20261030_v1 --batch-size 8 --threads 12
```

3. 전체 미완료0·1024차원·모델digest·원본 무결성을 실제 DB에서 검증한다. 완료 전 embedding_ready=true를 수동 지정하지 않는다.
4. 아래 자동 연결은 코드/모델/원천 상태를 다시 검토하고 명시적으로 시작한다. 현재는 실행하지 않은 명령이다. supervisor가 시작되면 코드/계약 hash 변경 및 단계 nonzero에서 정지하며 기존 실패 파일을 덮지 않는다.

```text
.venv/Scripts/python.exe -u -m research.marine_geollm_scie.runners.full_pipeline --execute --output outputs/scie_full_pipeline_20261030_v1 --embedding-dir outputs/dataset_embedding_completion_20261030_v1 --snapshot-dir outputs/scie_model_snapshot_20261030_v3 --run-dir research/marine_geollm_scie/runs/20261030_full_execution_v5
```

5. snapshot/profile/graph/baseline/report는 각각 실제 완료 상태를 확인한다. source freeze·DB identity·모델digest gate를 우회하지 않는다. 부분 실패는 원시 기록과 함께 별도 수정 에이전트가 검토한다. 단위검증과 첫 K1 결과만으로 논문 전체 완료를 선언하지 않는다.
